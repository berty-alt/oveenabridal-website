# 3. COLLABORATION WORKFLOW

GitHub must be the source of truth.

Use the following branches:

* `main`: stable production-ready code
* `develop`: integrated development code
* `codex/<feature-name>`: Codex work
* `claude/<feature-name>`: Claude work

Never push experimental work directly to `main`.

Before starting a task:

1. Pull the latest changes.
2. Read `TASKS.md`.
3. Check whether the task has already been assigned.
4. Mark the task as in progress.
5. Identify the files that will be edited.
6. Ensure the other agent is not editing the same files.
7. Create a dedicated branch.
8. Implement only the assigned scope.
9. Run formatting, linting, type checking and tests.
10. Commit the work.
11. Update `TASKS.md`.
12. Open a pull request or provide a precise handoff summary.

Create and maintain these collaboration files:

## `TASKS.md`

Every task must contain:

* Task ID
* Description
* Assigned agent
* Status
* Branch
* Files affected
* Dependencies
* Acceptance criteria

Allowed statuses:

* Backlog
* Ready
* In Progress
* Blocked
* Review
* Completed

## `DECISIONS.md`

Record important technical and product decisions:

* Date
* Decision
* Reason
* Alternatives considered
* Agent responsible
* Consequences

## `HANDOFF.md`

Each handoff must contain:

* Work completed
* Files changed
* Tests performed
* Known limitations
* Environment variables required
* Next recommended task
* Anything the next agent must not change

Do not rely on chat history alone. Important decisions must be recorded in the repository.

# 5. PRODUCT GOALS

The platform must:

* Present the bridal shop as premium and trustworthy.
* Make it easy to discover suitable dresses.
* Show accurate dress details and measurements.
* Prevent double bookings.
* Allow fitting appointment reservations.
* Support rental deposits and balances.
* Provide customers with clear booking status.
* Reduce manual WhatsApp administration.
* Work well on low-to-mid-range mobile devices.
* Protect uploaded photos and personal information.
* Be expandable without requiring a complete rewrite.

The platform must not:

* Claim AI previews provide exact fitting.
* Store customer photos indefinitely.
* expose private storage URLs.
* Allow two confirmed bookings for the same dress and overlapping rental dates.
* Process payments without server-side verification.
* Depend entirely on JavaScript for essential SEO content.
* display unavailable dresses as immediately bookable.
* place secrets in frontend code.

# 6. RECOMMENDED TECHNICAL STACK

Use the existing project stack if appropriate. For a new project, use:

## Application

* Next.js with App Router
* TypeScript with strict mode
* React
* Tailwind CSS
* A controlled component system such as shadcn/ui
* Server Components where appropriate
* Client Components only when required

## Backend

* Next.js server actions and route handlers, or a clearly separated backend service if justified
* PostgreSQL
* Prisma ORM or Drizzle ORM
* Zod for runtime validation

## Authentication

Use one of:

* Auth.js
* Supabase Auth
* Clerk only if explicitly approved

Required roles:

* CUSTOMER
* STAFF
* ADMIN
* SUPER_ADMIN

Authorization must be enforced on the server, not only hidden in the UI.

## Media

* Private object storage for customer uploads
* Optimized public storage for dress catalogue images
* Signed and expiring URLs for private media
* Cloudinary, Supabase Storage or S3-compatible storage

## AI Virtual Try-On

Use an abstraction layer that can support:

* FASHN API
* Another approved virtual try-on provider
* A mock provider for local development and testing

Do not tightly couple business logic to one AI provider.

## 3D viewer

Use:

* GLB/GLTF format
* `<model-viewer>` for the first implementation
* Three.js only if custom interaction is required

## Deployment

Recommended:

* Vercel for the application
* Managed PostgreSQL
* Managed object storage
* Error monitoring
* Automated CI checks

Do not purchase or activate paid services without approval.
